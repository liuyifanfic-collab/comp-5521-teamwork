# COMP5521 HTLC — Cross-Chain MST / ETH Exchange

A two-chain Hash Time-Locked Contract (HTLC) demo for **MST on Ethereum Sepolia**
and **native ETH on Arbitrum Sepolia**. The two contracts never call each other;
atomicity comes from a shared hashlock, a revealed preimage and the timelock
ordering `T_ETH < T_MST`.

This repository snapshot contains the A/B contracts and the D-role cross-chain
scripts and deployment tooling. The C frontend and the E report/presentation are
separate deliverables.

## Quick start — local two-chain, no funds

Requirements: Node.js 20+ and npm. The scripts use the project's existing
dependencies; no extra package is required.

```bash
npm ci --registry=https://registry.npmmirror.com --no-audit --no-fund
npm run compile
npm run local:demo
```

`local:demo` starts two independent Hardhat JSON-RPC nodes:

- `http://127.0.0.1:8545`, chain ID `31337` — MySimpleToken (MST) + ERC20HTLC
- `http://127.0.0.1:8546`, chain ID `421614` — ETHHTLC

It deploys the contracts, runs the successful swap, runs the timeout-recovery
scenario, writes `evidence/d-local-two-chain.json`, and stops the nodes. The
human-readable run is captured in `evidence/d-local-two-chain.txt`. The local
demo deploys the official Lab 3 `MySimpleToken` (the same token contract used
for the public testnet deployment) and does not depend on the test-only mocks
under `contracts/mocks/`.

To keep the nodes for manual commands:

```bash
npm run local:demo -- --keep-nodes
# or start them without running the scenarios:
npm run local:nodes
npm run deploy:local
```

## Testnet setup

1. Copy the template and fill in the placeholders:

   ```bash
   cp .env.example .env
   ```

   Required: `SEPOLIA_RPC_URL`, `ARBITRUM_SEPOLIA_RPC_URL`,
   `ALICE_PRIVATE_KEY`, `BOB_PRIVATE_KEY`.
   Alice owns MST and receives ETH; Bob owns ETH and receives MST. Both accounts
   need gas ETH on both chains.

   MetaMask works: create/use two **disposable testnet accounts**, open
   *Account details → Show private key*, and paste each 64-hex key into `.env`
   (the `0x` prefix is optional). Never use a mainnet account for this demo and
   never post a private key in chat.

2. If the team does not already have an MST on Sepolia, deploy the official
   COMP5521 Lab 3 token (no constructor arguments):

   ```bash
   npm run deploy:mst
   ```

   It deploys `MySimpleToken` ("My Simple Token", "MST", 18 decimals), mints
   1,000,000 MST to Alice by default, writes the MST address into
   `deployments/testnet.json`, and prints `MST_ADDRESS=...`. If you already have
   an MST address, set
   `MST_ADDRESS` and skip this step. `MST_MINT_TO` / `MST_MINT_AMOUNT` can
   override the mint recipient and amount.

3. Check configuration and connectivity:

   ```bash
   npm run doctor
   ```

   The doctor prints each chain's actual `eth_chainId`, contract code presence,
   account balances and whether the `abi/` handoff still matches the compiled
   artifacts. Before the HTLC deployment, the two HTLC-address warnings are
   expected.

4. Deploy the two HTLC contracts (no constructor arguments):

   ```bash
   npm run deploy
   ```

   This writes `deployments/testnet.json` and prints the two addresses. The
   scripts read addresses from that file if the matching `.env` variables are
   empty. Add them to `.env` if you prefer.

5. Run the complete successful swap:

   ```bash
   npm run swap:success -- --label demo-success
   npm run status -- --label demo-success
   ```

6. Run the timeout-recovery scenario:

   ```bash
   npm run swap:refund -- --label demo-refund
   ```

   On a public testnet this waits for the real timelocks. For a live
   demonstration, pre-create the refund swap with short timelocks and call
   `status` / `refund` separately when the deadlines arrive.

## Command reference

```bash
node scripts/cli.js doctor
node scripts/cli.js deploy-mst [--force] [--mint-to <address>] [--mint-amount 1000000]
node scripts/cli.js deploy [--chain eth|arb|both] [--network local|testnet] [--allow-stale]
node scripts/cli.js deploy --network local --with-mst
node scripts/cli.js secret --label <name> [--mst-amount 100] [--eth-amount 0.01]
node scripts/cli.js approve --amount 100
node scripts/cli.js lock --chain eth --label <name>
node scripts/cli.js lock --chain arb --label <name>
node scripts/cli.js verify --label <name> [--expect-status active|claimed|refunded]
node scripts/cli.js status --label <name> [--json]
node scripts/cli.js status --all
node scripts/cli.js claim --chain arb --label <name>
node scripts/cli.js claim --chain eth --label <name>
node scripts/cli.js refund --chain arb --label <name> [--fast-forward]
node scripts/cli.js refund --chain eth --label <name> [--fast-forward]
node scripts/cli.js success --label <name> [--dry-run] [--evidence <file>]
node scripts/cli.js refund-flow --label <name> [--dry-run] [--no-fast-forward]
node scripts/cli.js check-artifacts
```

Useful flags:

- `--json` keeps stdout machine-readable and sends progress to stderr.
- `--network local` uses the two local nodes and the throw-away Hardhat mnemonic.
- `--env-file <path>` loads a specific configuration file.
- `--mst-seconds` / `--eth-seconds` / `--min-gap` shorten the timelocks for a
  rehearsal. They must satisfy `ETH + gap <= MST`.
- `--fast-forward` (local only) advances the selected chain with
  `evm_increaseTime`; it is a test convenience and never used on a public chain.
- `deploy-mst` deploys the official Lab 3 MST token; `--force` allows replacing
  an existing configured token, and `--mint-to` / `--mint-amount` override the
  default 1,000,000 MST minted to Alice.

## Live-demonstration outline (four minutes)

1. **Prepare before the slot:** deploy contracts, fund Alice/Bob, pre-create the
   refund swap with short timelocks (`lock` on both chains), and verify it.
2. **Successful swap:** `npm run swap:success -- --label demo-success` — show
   the two `Locked` transactions, the verification table, Alice's ETH claim, the
   `Claimed` event secret, Bob's MST claim and the final `Claimed` statuses.
3. **Recovery case:** show `status` for the pre-created refund swap while it is
   still `Active` ("refund not yet valid"), then `refund` both sides after the
   deadlines. The refund flow also demonstrates the expected
   `SwapNotExpired` / `InvalidSecret` / `UnauthorizedReceiver` reverts.

Do not put a private key in a command or in the repository. Use `.env`
(ignored by Git) and keep the evidence files free of secrets.

## Security notes

All timestamps printed by the scripts and recorded in evidence are UTC ISO-8601
(for example `2026-11-16T05:23:03.000Z`); the demo machine may be in another
timezone.

- The swap preimage is written only to `.runtime/swaps/<label>.json` with mode
  `0600`; `.runtime/` is ignored by Git. The full preimage is not printed by
  default.
- `.env` is ignored; `.env.example` contains placeholders only. No key is ever
  logged. Private keys are read from the environment, never from CLI arguments.
- RPC URLs may contain provider API keys; treat them as configuration secrets
  and rotate them if they are ever exposed.
- Use disposable testnet accounts. If a private key was ever shared, stop using
  that account after the demo and move any remaining testnet balance to a fresh
  account.
- Before creating the submission archive, exclude `.env` and `.runtime/`; submit
  only `.env.example`. `.runtime/swaps/` contains the swap preimages.
- Every write checks the RPC's `eth_chainId` against the expected chain ID before
  sending a transaction.
- `swapId` is always taken from the `Locked` event and immediately checked with
  `getSwap`; the Solidity return value is not trusted.
- The preflight refuses to start when balances, gas, addresses or the timelock
  ordering are insufficient.
- `T_ETH < T_MST` with a safety gap is verified on both chains before any claim.
- The provider's response cache is disabled so a just-mined transaction cannot
  cause a stale nonce on an automine chain.
